Public-Key Crypto Lab

Two keys instead of one: build an RSA key pair by hand, send a secret to someone you've never met, and sign a message so nobody can fake it.

The problem with one key

A Caesar cipher (or a modern one like AES) is symmetric: the same key locks and unlocks. That means the sender and receiver have to agree on a secret key before they can talk privately. How do you do that with a website you've never visited, over a network anyone can listen to?

Public-key cryptography uses two mathematically linked keys. The public key works like an open padlock: you can hand out copies to the whole world, and anyone can snap one shut on a box. The private key is the only thing that opens it, and it never leaves your hands. The most famous recipe is RSA (Rivest, Shamir, and Adleman, 1977). Build a key pair step by step below.

1

Pick two prime numbers, p and q

A prime is divisible only by 1 and itself. Real RSA uses primes over 300 digits long; we'll use small ones so you can check the arithmetic.

2

Multiply them: n = p × q, and compute φ(n)

n is part of the public key. φ(n) (“phi of n”) counts the numbers below n that share no factor with it; it's easy to compute if you know p and q, and is kept secret.

3

Choose the public exponent e

Any e between 1 and φ(n) that shares no common factor with φ(n), meaning gcd(e, φ(n)) = 1. Click one. (Real systems almost always use e = 65,537.)

4

Compute the private exponent d

d is the number that “undoes” e: multiply them and divide by φ(n), and the remainder is 1. In symbols, e × d ≡ 1 (mod φ(n)). The extended Euclidean algorithm finds it quickly; here are its steps.

Once d is computed, p, q, and φ(n) are no longer needed — but they must stay secret, because anyone who learns them can recompute d.

Encrypt and decrypt a number

encrypt: c = me mod n   ·   decrypt: m = cd mod n

The message must be a number m smaller than n. Text becomes numbers using character codes, so you can also type a single letter.

How the computer does the power: square-and-multiply

  • Why it works: because e × d leaves remainder 1 when divided by φ(n), raising to the e-th power and then the d-th power always brings you back to m (this follows from Euler's theorem). The two exponents undo each other, just like a lock and its key.
  • Why it's secure: everyone knows n and e. To find d you need φ(n), and to get φ(n) you need p and q, which means factoring n. Multiplying two primes is instant; splitting n back into them is believed to be extremely hard once n has hundreds of digits.
  • Why it's fast: square-and-multiply needs only about one step per bit of the exponent, and taking mod n after each step keeps the numbers small.

Sending a secret to someone you've never met

Alice wants to send Bob a private message. They have never met and share no secret. Worse, Eve the eavesdropper can read everything that crosses the network. Public-key crypto solves it in four steps:

  1. Bob generates a key pair and keeps the private key to himself.
  2. Bob publishes his public key — Eve can see it too, and that's fine.
  3. Alice encrypts her message with Bob's public key and sends it.
  4. Only Bob's private key can decrypt it. Not even Alice can undo it.

  • Encrypt with the receiver's public key. Alice needed nothing secret from Bob, and Eve learned nothing useful from seeing the public key.
  • Hover a byte and look closely: identical letters encrypt to identical numbers. That's the same weakness the Caesar cipher had, so this textbook RSA could be broken with frequency analysis. Real RSA adds random padding (OAEP) so the same message encrypts differently every time.
  • In practice RSA is slow, so it's only used to send a short random symmetric key (for AES); the rest of the conversation uses that key. HTTPS works this way.
  • Key size is everything. Have Eve factor n at each size. A real 2048-bit n has 617 decimal digits; the best known methods would need far longer than the age of the universe on today's computers.

Proving who wrote it: hash + private key

Encryption keeps a message secret. But how does Bob know a message really came from Alice, and that nobody changed it along the way? Run RSA backwards: Alice does something only her private key can do, and anyone can check it with her public key.

Alice doesn't sign the whole message. RSA can only handle a number smaller than n, and is slow. She signs its hash instead (the fixed-size fingerprint from the Hashing Lab). Since changing even one character changes the hash completely, signing the hash is as good as signing the message.

  • Non-repudiation: only Alice's private key could have made a valid signature, so she can't later claim she didn't sign the IOU.
  • Hash + signature are a team: the hash catches any change to the message; the private key ties that hash to Alice.
  • This is how cryptocurrency works. A Bitcoin “wallet” is really a private key. Every transaction (“send 0.1 BTC to …”) is hashed and signed with it, and every node on the network verifies the signature with the matching public key before accepting it. (Bitcoin uses elliptic-curve signatures rather than RSA, but the idea is the same.)
  • Toy shortcuts: our n is tiny, so we sign only the first bits of the hash. Real systems use 2048-bit RSA with padding (RSA-PSS) or elliptic curves and sign the full hash.
