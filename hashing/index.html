What's a hash?

A hash function takes an input of any size — one letter, a password, an entire movie — and boils it down to a short, fixed-size value called a hash (or digest). Think of it as a fingerprint for data. The one below is SHA-256, the same function used by HTTPS, password storage, Git, and Bitcoin. Its output is always 256 bits, usually written as 64 hexadecimal digits.

Type in the box and watch the fingerprint change. Hover any hex digit to see the 4 bits it stands for.

  • Deterministic: the same input always gives the same hash — on any computer, forever.
  • Fixed size: “a” and a 500-page book both produce exactly 256 bits.
  • Avalanche effect: change one character and about half the bits flip. Try it in the comparison box below.
  • One-way: you can't run it backwards. Given only a hash, the only way to find the input is to guess and check.

A hash function is just math

SHA-256 looks like magic, but at heart a hash function is any recipe that turns input into a number in a fixed range. You can build a basic one with arithmetic you already know. Every character already is a number (its character code, e.g. A = 65), so we combine those numbers and then use the modulo operator (mod, the remainder after division) to force the result into a fixed range of m “buckets”: 0 … m−1.

This is exactly how a hash table (a Python dict, a Java HashMap) decides where to store each key. Pick a recipe below and watch it work step by step.

Why Bitcoin cares about the bits

A cryptocurrency like Bitcoin records transactions in blocks. To add a block, a computer must find a block whose SHA-256 hash, read in binary, starts with a required number of 0 bits. The only adjustable part is a throwaway number called the nonce. Because hashes are unpredictable, there's no shortcut: you try nonce 0, 1, 2, 3… and hash each until you get lucky. That guessing is called mining, and the winning nonce is the proof of work.

  • Hard to find, easy to check: finding the nonce may take millions of guesses; anyone can verify it with a single hash.
  • Each extra 0 bit doubles the work. A random hash starts with N zero bits about once every 2N tries.
  • Tamper-evident: change even one character of a mined block and its hash changes completely — the proof of work is gone and must be redone.

Real numbers: this page hashes a few hundred thousand times per second. The Bitcoin network as a whole performs hundreds of quintillions of hashes per second, and its difficulty demands roughly 75–80 leading zero bits — that's why a real block hash, written in hex, begins with a long run of zeros like 00000000000000000002a7c4…. (Bitcoin also hashes twice, SHA-256 of SHA-256, and the block contains the previous block's hash, chaining them together.)
